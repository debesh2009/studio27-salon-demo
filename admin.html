Demo mode. This dashboard is a user-interface demonstration. Every name, date and status below is invented sample data for showing the layout — none of it is a real customer booking. The dashboard is not connected to the public booking form, has no database behind it, and has no real sign-in: a demo login screen exists, but its username and password sit in plain text in login.js for anyone to read. That screen now sets a browser-side session flag which this page checks before it loads, but that is not real protection — the flag can be set by hand in devtools, so this page can still be opened directly by anyone who does. Changes you make here live only in this browser tab and disappear on reload.

      How this demo works

      Dashboard mode
      Demo — sample data only
      Data source
      Invented sample records inside admin.js
      Storage
      None. Changes reset when the page reloads.
      Connected to booking form
      No. The public WhatsApp form and this dashboard are separate.
      Database
      Not implemented — planned for the next phase
      Authentication
      Demo login only. The credentials are hard-coded in login.js and readable by anyone, and although admin.html now checks a browser-side session flag set at sign-in, it is still not protected — the flag can be faked, so direct access cannot be truly blocked.
      WhatsApp request number
      916297519708 (authorised testing number, set in script.js)

      The demo sign-in screen is decoration, not protection. login.html checks a username and password that are written in plain text in login.js, so anyone who views the page source can read them. It stores no session beyond a single browser-side flag, and that flag is all that guards this dashboard: anyone who sets it by hand can open admin.html directly. It exists only so the demonstration has an entry point. Real owner authentication — verified on a server, with hashed credentials — arrives with the database phase.
